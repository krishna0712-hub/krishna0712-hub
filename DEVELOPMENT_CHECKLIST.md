# Development Checklist

A lightweight checklist for building and presenting portfolio projects with professional habits.

## Before coding

- [ ] Define the user problem in one sentence.
- [ ] List the main user flow and required screens.
- [ ] Choose a small first version that can be completed.
- [ ] Record the stack, setup steps, and known constraints.

## During development

- [ ] Keep files and functions focused on one responsibility.
- [ ] Use clear names for variables, components, and folders.
- [ ] Test the main flow after each meaningful change.
- [ ] Check responsive behavior on mobile and desktop.
- [ ] Avoid committing secrets, generated files, or unused code.

## Before publishing

- [ ] Add a useful README with features, screenshots, and setup steps.
- [ ] Verify links, forms, navigation, and error states.
- [ ] Include a short list of future improvements.
- [ ] Review the final project from a user's point of view.
- [ ] Write a commit message that explains the change clearly.

## Definition of done

A project is ready to showcase when another developer can understand its purpose, run it locally, try the main flow, and see what could be improved next.
